## 主な変更：「手厚さの設計」を第21章として追加

v3 では、MusicGrowの**自己満足支援を一段階深める**ための章を追加しました。これまでの章は「何を実装するか」を定義していましたが、第21章は「**どうユーザーに寄り添うか**」を定義します。

## 1. 第21章「手厚さの設計」の新規追加

### 1.1 章の構成

- 21.1 「手厚さ」の定義（即時／振り返り／道、3層の自己満足）
- 21.2 手厚さの10項目（MVP・早め・後で の3区分）
- 21.3 手厚さの判断基準（4つの問い）
- 21.4 「手厚さ」と「過剰さ」の境界

### 1.2 手厚さの10項目

| ID | 項目 | 実装時期 |
|---|---|---|
| ① | 書いた直後の余韻演出 | MVP |
| ② | 寝る前にもう一度見せる | 早め |
| ③ | ひとこと音読モード | 後で |
| ④ | 文字数の節目記念 | 早め |
| ⑤ | 同じ曲との会話◯回目表示 | 早め |
| ⑥ | 季節の振り返り | 後で |
| ⑦ | あの日の天気連動 | 後で |
| ⑧ | 書きかけ保存 | MVP |
| ⑨ | 削除しない、アーカイブにする | MVP |
| ⑩ | 通知しない（明文化） | MVP |

### 1.3 重要な決定事項：「通知しない」を明文化

⑩について、これは実装ではなく**やらないことの明文化**です。

「ひとことを書きませんか」のようなプッシュ通知は MusicGrow では絶対にしません。通知は自己満足の世界に他者の声を入れる行為。**通知しないこと自体が、最大の手厚さ**という思想を残します。

### 1.4 手厚さの判断基準（新規）

新機能追加時に毎回問いかける4つの質問：

- 書いた人を、ニヤッとさせるか？
- 他人の目が入らないか？
- 急かさず、責めないか？
- 数年後の自分が嬉しいか？

すべてYesなら追加候補。一つでもNoなら設計し直し。

## 思想的な意義

v3 の追加は、MusicGrowが「**機能を増やすアプリ**」ではなく「**ピンポイントで深く寄り添うアプリ**」であることを明文化するものです。

第21章の3層モデル（即時／振り返り／道）は、今後の機能判断の補助線になります。「これは即時の満足？それとも道の満足？」と問うことで、機能の役割が明確になります。

また、「手厚さ」と「過剰さ」の境界を引いたことで、機能を追加する誘惑にブレーキがかかります。**MusicGrowは"足し算"ではなく"選び抜き"のアプリ**であることを、設計レベルで担保しました。
